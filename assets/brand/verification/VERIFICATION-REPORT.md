## 一、资产完整性

- 19 个文件齐全：母版/小尺寸/32px/浅色/单色 SVG、1024→16 全套 PNG、字标 SVG、BRAND-GUIDE.md、两张预览图。
- 所有 SVG 通过 XML 解析；所有 PNG 宽高与文件名一致（16/24/32/48/64/128/256/512/1024）。
- 1024 母版：四角透明（alpha=0）✓；中心交叉处为前链色 ✓；两条横档色 ✓。
- `DNACode-icon-kit.zip` 与解压目录内容一致。

## 二、16px 可读性验证（重点项）

方法：把每个尺寸的 PNG 逐像素分类为「底板 / 后链 / 前链 / 横档 / 浑浊混合」五类，输出结构图对比（同一分类标准）。

| 尺寸 | 版本 | 横档像素 | 前链像素 | 后链像素 | 浑浊混合 |
| --- | --- | --- | --- | --- | --- |
| 16px | 现行旧版 | **0**（完全不可识别） | 4 | 20 | 有 |
| 16px | **精修提案** | **12**（上下两条 6px 清晰横条） | 18 | 34 | **0** |
| 24px | 精修提案 | 32（上下各 16） | 48 | 46 | 0 |
| 32px | 精修提案 | 24（上下各 12） | 50 | 72 | 0 |

- 结论：现行版 16px 中横档/前链基本糊掉；精修版在 16px 下「X 交叉 + 两道横档」的梯子结构成立，且零浑浊混合像素。
- 放大对比图（浅色 + 深色背景）：见下方产物 `compare-old-vs-refined.png`。

## 三、打包流水线实测（设计师点名的风险点）

设计师在 BRAND-GUIDE 中指出："one-source conversion may discard the small-size optical tuning"。实测：

1. 用官方 `tauri icon` 从精修 1024 母版单独转换 → 生成的 16px 帧中**横档像素 = 0**，前链/后链变细糊——**风险属实**。
2. 手工装配测试 ICO（艺术指导 16/24/32 + 母版 48/64/256，与官方相同的 6 帧结构）：
   - 每一帧的字节与套件源 PNG **SHA1 完全一致**；
   - Windows 底层 API（LoadImage + DrawIconEx）实测 16/24/32/48/64/128/256 全部正常加载渲染；
   - 与现行正式版 ICO 的格式完全对等（全 PNG 帧）。
3. 对照图：`onesource-vs-artdirected.png`；测试图标：`DNACode-icon-test.ico`（在资源管理器里可直接查看各视图效果）。

## 四、待补 / 待确认（不阻塞方向，但集成前需要）

1. **浅色版字标（缺件）**：现字标文字填充 #E6E9F0，在浅色底上不可见（实测截图见 `wordmark-light-problem.png`）。README / GitHub 浅色主题需要一版深色文字字标。
2. **字标转曲（建议）**：现字标使用实时文字（依赖 Inter/Segoe UI 字体栈），在无该字体的环境（Linux、GitHub 渲染）字形会漂移。建议提供文字转曲（outline）版本。
3. **应用内小标派生确认**：套件未包含"无底板小标"（工具栏 20px / 欢迎页 46px 用）。工程侧将按尺寸策略派生：工具栏用 small 几何（≤32 规则）、欢迎页用母版几何（≥48 规则），颜色走主题变量（深色底 #315FA8 后链 / 浅色底 #9AB9EB）。请设计师过目此规则。
4. 文档小问题（顺手校对）：BRAND-GUIDE 中 16px "opaque background" 与实际文件的透明四角不符（文件正确、措辞小误）；底板色写作 "#151B26 to #1B2230" 与母版渐变 "#1B2230 → #10151E" 未对齐。

## 五、集成方案（待方向确认后执行）

1. **套件入库**：`assets/brand/`（含全部 SVG 源 + BRAND-GUIDE.md，符合"include the SVG sources with the project"）；`assets/logo.png` 替换为精修 1024。
2. **重制平台图标** `src-tauri/icons/*`：自定义装配（ICO 艺术指导小帧；ICNS 使用与官方相同编码库），不用单一源转换。
3. **应用内小标更新**：工具栏 / 欢迎页 / 编辑器空状态，按第四节第 3 条规则。
4. **清理**：zip、根目录散图、验证目录；README 字标（待浅色版到位）。
5. **真实场景验证**：Windows 本地重新构建安装包（任务栏/安装器/资源管理器）；macOS / Linux 由 CI 草稿构建验证。
